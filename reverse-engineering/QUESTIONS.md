# 研究问题

| 编号 | 要回答的问题 | 当前证据 | 下一步 |
|---|---|---|---|
| RE-01 | 本地启动、资源加载和存档如何衔接？ | 七个原版 JS 已由 REA 解析，证据图仍有动态关系未知项。 | 沿 `rogue.js`、`boot.js`、`wenilla.js`、`addons.js`、`saves.js` 的具体调用追踪；需要行为结论时再做受控运行观测。 |
| RE-02 | 单机／菜单的 `/presence` 与合作大厅如何触发？ | 既有封装 QA 观察过单机状态上报失败但战斗正常；本轮 JS 分析未恢复 WASM 内部触发条件。 | 在对应核心定位 URL 引用、模式与调用频率，区分可选上报和必要合作连接。 |
| RE-03 | 模型、贴图和技能特效通过哪些表与路径加载？ | 资源索引存在 M2、BLP、WMO 和 Creature／Item／SpellVisual DBC。 | 固定一项角色或技能做映射追踪，再验证单项资源替换；记录帧率／显存影响。 |
| RE-04 | 技能伤害、冷却、生命、经验和掉落到底由哪里计算？ | 暂无可写数值插件 API 的证据；表文件名称不能证明实际计算位置。 | 先配置原生分析提供方并明确版本，从一个技能的一次伤害追到状态更新，建立输入／输出验证。 |
| RE-05 | 修改规则后，单机和朋友合作如何保持一致？ | 当前版本未完成规则修改同步验收。 | 确认主机／服务端的计算归属和协议，再决定统一修改客户端或独立合作方案。 |
| RE-06 | 能否逐步重建可维护的原生游戏实现？ | 目前只有封装源码、发布二进制与局部 UI 补丁。 | 从已经验证的独立函数和资源格式逐项重建、对比；不把伪代码／WAT 当原始 Rust 源码。 |

先完成目标与工具接入，再逐项缩小问题。每项结论写明原始版本与 SHA-256、REA Evidence ID、静态观察／推断／运行验证，以及仍未覆盖的范围。
