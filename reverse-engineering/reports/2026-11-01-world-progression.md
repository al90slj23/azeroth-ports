## 普通刷怪：候选、加权、预算、补足

主循环的运行tick条件成立后调用948。此函数包含多种波次和事件，本轮追通的是其中持续普通刷怪与Boss时间表路径。

948在frame`+264`保存`t=G.f32(2064)/60`。从地图普通/精英表按72B遍历，候选要求`elite_flag==0 && unlock_minute<=t`，形成u32定义下标数组；传给20145。另有精英/特殊波次路径，不能把此过滤规则推广到每一种生成。

20145对给定候选的权重计算为：

```text
age = max_nonNaN(t - def.unlock_minute, 0)
weight = min_nonNaN(4, 1 + .5*age) / def.cost60
sum = 按候选顺序逐项f32累加(weight)，初值-0
r = F32475(G+1528, 0, max_nonNaN(.001, sum))
逐个候选：若 r < weight，返回该定义下标；否则 r -= weight
若非空列表扫描耗尽，返回列表首项；空列表进入原始panic路径
```

fallback首项由结构分支证明：20145行403的`br_if 1 @2`落到行416，跳过行410至411的`local9→local1`重赋值，随后从原始候选base读取。普通命中在行378跳到409后使用当前候选指针。不能凭直觉实现成“最后一项”。随机浮点辅助函数32475及其完整RNG协议本轮未独立建模。

948的持续刷怪不是固定的“每秒N只”。可读算法如下，其中`B=G.f32(2128)`为剩余预算，`K=G.f32(2132)`是普通怪死亡累计成本，`dt`为参数1：

```text
K *= D26229(dt / -12)
base = .6 * (.9 + .32*t + .025*t*t)
R = 1
遍历活单位：若 U.u32(0)==0 且 U.i32(244)!=-1：
    R = min_nonNaN(R, bossDef.u8(68)!=0 ? .3 : .45)
    # bossDef指针来自U+256；普通单位在5684中将U+244写为-1
E = endless启用时 1.5+.1*e，否则1
catchup = clamp((K/12*1.25) / max_nonNaN(.001,base*R*E), 1, 3)
M = mode2294==1 ? 1+.312*b*n : 1
B += dt * (base*R*E*catchup * M)
```

这里`b=.7`适用于地图index<3，其他为1；`n=f32(wrap_u32(G.u32(2252)-1))`。`e=max_nonNaN((G2064-G404)/60,0)`仅在`G400==1`的无尽后段启用。两处原始`E`条件分别检查`G2280==1`和`G2280!=0`，对正常0/1布尔值等价，移植时应保留区别。`D26229`尚未差分确认，不能把上式视为已完成的位级可执行模型。

当`B>=1`时按20145选择定义，若定义成本`def+60>B`则停止。调用5684实际创建：成功扣成本；失败把预算收敛到`min_nonNaN(cost,B)`后停止。一tick最多8次成功预算生成，原始guard为循环counter<7后递增。

预算循环后还有最低密度补充：

```text
target = sat_u32(min_nonNaN(36,(4+1.6*t)*R) * M)
aliveNormal = count(U.u32(0)==0 && U.ptr(284)!=0 && !normalDef.u8(68))
最多尝试 min(3, saturating_sub_u32(target,aliveNormal)) 次5684
```

因此最低密度生成不能额外扣上一段预算；二者是相邻的不同路径。地图特殊波型、精英事件计时和环境事件还没有全部还原。

## 5684：416B单位及普通/精英强度


`elite/normal`命名有caller与伤害判据依据：5684函数内行243至245读`def.u8(68)`到local6；行259至267明确真分支调用95640、假分支95641。同一字段在行514至516读到local9，再在行750至752写入`U.u8(412)`。933行221至235中local14为`U+416`，`local14-172`与`local14-4`分别为`U244/U412`；只有`U244!=-1 || U412==1`进入tag19的加区。既有[实际伤害报告](2026-11-01-damage-core.md)已将tag19与面板“Vs Elites”交叉定位。这是从定义flag→spawn分支→单位flag→实际伤害条件的证据，不是按曲线系数大小猜名字。提取器新增了这5处连续指令guard。

## 独立可执行的两条曲线

`reconstruction/core_spec/enemy_scaling.py`使用共享`binary32.py`，每一步以精确有理数求值再RNE舍入；输入输出均为uint32 binary32位模式。保留原WASM求值次序：

```text
first  = add(mul(t,.1),1)
second = mul(t,mul(t,.036))
third  = mul(t,mul(t,mul(t,cubic)))
result = mul(z,add(add(first,second),third))
```

因此没有改成Horner形式或binary64 `pow()`。95640/95641的原body各46字节、无内部引用；微模块把外部函数index映射为0/1，但两个body完全不改，独立重读code section再次逐字节比较；原body SHA分别为`442e45ccda27e06f92ae6e9de53ed80e141a33e4377779c9c06b9184d632e432`、`c351aee9ba131c59f7a97e029e782db6ea97f0dcbebed71556d9d1e940013a18`。

实际差分结果：

| 组 | 例数 |
| --- | ---: |
| 特殊binary32值交叉：±0、次正规、极值、无穷、NaN及邻近值 | 1,250 |
| 实际地图系数/游戏分钟与相邻binary32表示 | 1,386 |
| 固定seed原始32位模式 | 20,000 |
| 固定seed正常游戏范围 | 2,000 |
| 合计 | 24,636 |

21,653组非NaN结果按全部uint32位比较相同，包括无穷与±0；2,983组只比较双方都为NaN。NaN的payload、符号、signaling状态不作位级声称。固定seed `0xa2e95640`，Node v22.23.4，0差异，原body字节同一，微模块SHA `79e3fcb0097a9eb14c57b70aff40b59a2bb5c43b38d5812a853833c9c2ab8163`。差分是确定性证据，不是穷举每函数`2^64`输入对的证明。
