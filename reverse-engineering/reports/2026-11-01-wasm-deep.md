## presence：已定位到函数实现

发送函数全局索引 **25238**，本地 code-body 索引 24360，原文件字节范围 `[49,300,389, 49,301,023)`，函数体仅 634 字节；函数体 SHA-256 为 `82295aec1eaf8efb8ed737c0f7854f630337a92856956aabd289d027337a0a66`。

- 函数内的 `call 630` 精确对应原始 JS glue 的 `__wbg_sendBeacon_f7b8b5a89dd3f75e` 导入。
- URL 在数据段 897，原文件偏移 77,510,766，线性内存地址 1,486,550；初始化函数 905 中有此地址的唯一已观察 `i32.const` 引用。
- 全模块直接 `call 25238` 的调用者是全局函数 **12692** 和 **15920**。这不包含间接调用分析。
- 分支使用四个静态字符串：`menu`、`lobby`、`solo`、`coop`。
- 同模式使用阈值 **60**，首次或模式变化使用最小阈值 **10**。两者来自真实浮点比较指令；按引擎时钟上下文推断单位为秒，本轮没有运行测量。
- 模式字节比较辅助函数 **81718** 逐字节比较，全部相等时返回 0，否则返回第一对不同字节的差；因此可确认发送函数的零值分支表示模式未变。
- 发送前就写入最后时间、已发送标记和模式。`sendBeacon` 的布尔结果没有用于回滚这些字段；没有等待服务器响应的指令路径。

以下为人工恢复的等价结构草图，字段名和参数角色为解释用途，并非找回的 Rust 标识符：

```text
if destination_state_is_unavailable:
    return
mode = in_run ? (co_op ? "coop" : "solo") : (co_op ? "lobby" : "menu")
delta = sent_before ? current_clock - last_clock : current_clock
if sent_before and delta >= 60:
    emit = true
else:
    if sent_before and mode == previous_mode:
        return
    if not (delta >= 10):
        return
last_clock = current_clock
sent_before = true
previous_mode = mode
payload = format_presence_fields(...)
navigator.sendBeacon(destination, payload)
```

时钟字段位于所传时间对象的偏移 92；其确切 Rust 类型和秒单位尚属推断。字符串数据有 `id=`、`;mode=`、`;platform=`、`;v=`，但标识生成和持久性没有在本轮追完。可选上报不等于合作数据连接；该发现不能证明全部联网行为已经穷尽。
